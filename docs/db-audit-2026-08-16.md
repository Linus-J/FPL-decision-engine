# Database audit — 2026-08-16

Full interrogation of `fpl_bot_v2.db` before the GW1 deadline: every table
profiled, every all-null and constant column explained, entity resolution
measured across sources, and time-sensitive data refreshed.

**Seven real defects found.** Four were mine, introduced earlier the same day.
The audit method that found them was profiling the data itself — every one had
passed the test suite.

---

## Defects found and fixed

### 1. A Triple Captain recorded as played in GW1

The worst of them. `decision_log` contained a `chip` row for gameweek 1,
before a ball had been kicked, so `chips_used_this_season()` believed the
chip was spent for the whole first half of the season.

Cause: making the cold start persist its projections (a display fix, so the
site and dashboard had numbers instead of nulls) meant `player_projections`
was no longer empty pre-season. `_run_decision_cycle` branched on
`projections.empty`, so it took the **in-season** path, ran `recommend_chip`,
and burned the chip.

Whether it is a cold start is a property of the *season*, not of what happens
to be persisted. Now branches on `season_has_played_history`.

### 2. Every persona writing the real bot's projections

Same root cause. `player_projections` has no persona scoping and
`get_latest_projections` takes `MAX(created_at)`, so whichever of the 90
personas ran last decided what the real bot, the site export and the
dashboard all read. **235,720 rows across 83 batches**; now 2,840 in one.

### 3. Clean-sheet probabilities were inverted

`_cs_from_h2h` computed `home_cs = draw + away_win * 0.3` — that is P(the
*home* team fails to score), attributing home clean sheets to away wins. A
fixture priced 0.806/0.132/0.062 returned **0.151 for the dominant side and
0.374 for the underdog**: inverted, and each side handed the other's number.
`features.py` feeds these to the minutes model as `my_cs_prob`/`opp_cs_prob`.

Replaced with the model's own Poisson — `exp(-λ_opponent)`, the same closed
form `assemble.py` uses — rather than a re-swapped heuristic. Same fixture now
gives 0.563 and 0.075.

### 4. The prior-league tier projecting everyone at the floor

`prior_league_stats` has `goals90`/`assists90` populated (7,413 and 7,097
non-zero rows) and `npxg90`/`xa90`/`sca90` **entirely zero** — the FBref
prior-league scrape only got the basic stats. `_prior_league_projection` used
precisely the zero ones, so all 28 league-tier players projected at the 2.0
floor and a genuinely good foreign signing was invisible to the optimiser.
Falls back to raw output; 57 players now clear the floor, topped by Rashford
at 4.31.

### 5. Two set-piece takers silently lost

The depth-chart file produced 102 roles and the table held 100.

- **Schär** is spelled "Schär" under free kicks and "Schar" under corners.
  Keyed by the raw name those became two roles for one player, and the upsert
  on `(player_id, season)` meant the second erased the first — his free-kick
  duty vanished.
- **"Pedro"** resolved to Pedro Neto on his first name, so João Pedro's
  penalty duty was assigned to Neto and then overwritten by Neto's own
  entries. **Chelsea's second penalty taker disappeared entirely.**

Variants now merge on the normalised name; genuine ambiguity is reported and
skipped rather than guessed.

### 6. `ß`/`æ`/`œ` dropped rather than transliterated

NFKD does not decompose them, so the ascii pass deleted them: **"Groß"
normalised to "gro"** — a truncated stem that cannot match an English source's
"Gross". Latent rather than live (our own spelling truncates identically), but
it would have bitten the first time a source spelled him the English way.

### 7. `cs_probability` never populated

Covered separately: `assemble.py` had each player's per-scenario clean sheet
internally but never surfaced it, so the column was 0.0 on every row ever
written and `plot_analysis.py`'s chart was permanently blank.

## Explained, not defects

| Observation | Why |
|---|---|
| `btts_prob` always NULL | The Odds API's `/odds` endpoint **rejects the market** (HTTP 422, verified). Cannot be sourced. `features.py` reads it via `COALESCE(..., 0.5)`, so it is a constant contributing nothing to the minutes model. |
| 20+ `player_match_events` columns all zero | FBref supplies defensive actions but not passing/chance stats. Affects only the historical bonus recompute, which still matches FPL's awarded bonus on **88.9%** of rows (mean error +0.012) — the missing inputs are largely compensated. |
| `teams.strength_*` all zero | FPL has not published them yet; `team_season_strength` is used instead. |
| `players.form`, `transfers_*` zero | Genuinely zero pre-season. |
| `fixtures.team_h_score` NULL, `finished` 0 | Season has not started. |
| `projection_samples` empty | The cold start produces no Monte Carlo draws. |
| `player_setpiece_roles.key_passes_per_game` zero | A published taker list has no opinion on key passes; the partial write leaves it for the Understat path. |
| `sim_managers.max_ownership_differential` constant | Not swept — it is inert until ownership data exists. |

## Follow-up, 2026-08-17

Re-auditing the odds path the next day turned up three more, including a
regression introduced by defect 3's own fix.

### 8. The clean-sheet fix was applied to serving but not training

Defect 3 corrected `data/ingestors/odds_api.py` (live) and left
`scripts/backfill_odds.py` (historical) alone — whose helper documented itself
as *"mirrors the live odds_api heuristic so historical and live features are on
the same scale"* and stopped doing so the moment the live one changed.

Both feed the same `my_cs_prob`/`opp_cs_prob` columns, so the minutes model was
fitting coefficients on inverted clean sheets and applying them to correct
ones. A consistent error a model can absorb; a **sign flip between fit and
inference** it cannot. Worse, briefly, than the original bug.

The derivation now lives once, in `projection/team_goals.py`, with both sites
calling it — a comment cannot hold an invariant that spans two files. Re-ran
the backfill: of 744 strong home favourites, **0** now have `home_cs <=
away_cs`.

### 9. Every odds feature was about to go inert for the whole season

`historical_fixture_odds` is a football-data.co.uk backfill of **finished**
seasons, so it ends at 2025-26. `minutes_model._build_features` calls
`load_fixture_odds()` and nothing else, on training and prediction alike — so
every 2026-27 row would have taken the `COALESCE` defaults: three constants,
for 38 gameweeks, in a model fitted on five seasons where they varied.

Nothing would have raised. A defaulted column is indistinguishable from a
populated one everywhere downstream. `fixture_odds` was full the whole time and
`load_live_odds_asof` existed for exactly this purpose, wired to nothing.

### 10. `btts_prob` was never a feature at all

Not merely unsourceable, as recorded above. The training table stored the
**over-2.5 probability under that name** — a documented proxy, and identical on
all 1900 rows — while the live API rejects the BTTS market, leaving it NULL and
pinned at 0.5 when served. So the model fitted a coefficient against a variable
spanning 0.341–0.81 and applied it to a constant. Replaced by `over25_prob`:
same signal, populated on both sides, under its own name.

### 11. Double gameweeks collapsed into a single fixture

The worst of the second pass. Per-fixture features were merged on
`(player_id, gameweek, season)` — but in a **double** gameweek a player has
two rows under that key, against different opponents at different venues. The
merge deduped the pair and copied one fixture's features onto both:

| Feature | Rows given the wrong fixture's value |
|---|---|
| `opp_defence_strength` | 2,716 |
| `opp_attack_strength` | 2,679 |
| `my_cs_prob` / `over25_prob` | 2,751 |
| `is_home` | 1,481 |

A home-then-away double gameweek was scored as two home games. The same path
runs at prediction time, so a live DGW would mis-price one of its two
fixtures — and double gameweeks are exactly where chip and transfer decisions
are made. Now keyed on `opponent_team_id` too, via a shared helper that raises
rather than degrading if a caller drops it.

### 12. Seven model features were constant in training

`is_penalty_taker`, `penalty_xg_per_game`, `is_set_piece_taker`,
`key_passes_per_game`, `injury_severity`, `press_sentiment` and `is_bgw` are
identically constant across all five backfilled seasons — their sources only
exist for the season being played.

Constant is merely useless while it lasts. It turns harmful once the current
season starts filling those columns in: the model retrains on all seasons
every run, so a column that is zero for five seasons and non-zero only for
2026-27 is a perfect *"this row is the current season"* indicator, and
gradient boosting will split on it. The same train/serve skew as the odds
features, in the opposite direction. They are now pinned to their training
value at prediction time.

### 13. The press sentiment scorer inverted its own signal

Substring containment got **8 of 13 live rows wrong**. `"available"` is a
substring of `"unavailable"`, so a player described as unavailable scored
**+1.0**. `"out for"` matched *"hook it out for a throw"* and *"deflected out
for a corner"* — ordinary match commentary the scraper picked up alongside
team news — and scored them as long-term absences.

Matching is now word-bounded and `"out for"` requires something
absence-shaped after it. That in turn broke plurals containment had caught
(`"fitness doubts"` scored 0.0), which is now explicit and tested — found by
re-scoring the live rows, not by the suite. The stored rows were re-scored
from their raw quotes rather than discarded.

## Third pass, 2026-08-17

Prompted by a re-scrape that reported success and changed nothing.

### 14. Team strengths were FPL's pre-season placeholders

The largest remaining defect. Until a season starts, FPL's bootstrap returns
`strength_attack_*` and `strength_defence_*` as **0** and `strength_overall_*`
on its **1–5 tier** — Arsenal came back as `overall_home=4, attack_home=0`.
Those were copied verbatim into `team_season_strength`:

| Season | `strength_overall_home` | non-zero attack ratings |
|---|---|---|
| 2021-22 … 2025-26 | 975 – 1355 | 20/20 |
| **2026-27** | **2 – 4** | **0/20** |

Every FDR feature would have been off-scale for the entire live season, four
of six pinned to zero, `attack_vs_defence` collapsing to 0 against ~1.0 in
training. `load_fixture_difficulty` could not rescue it — its `COALESCE` fires
only for a *missing* row, and a row full of zeros is present.

Placeholders are now stored as the neutral **1200** (the column's own default),
which costs nothing and keeps the scale the model understands, and
self-corrects when FPL publishes. The gate compares the current season against
the other seasons in the table rather than a hard-coded range.

### 15. The prior-league re-scrape could not re-fetch, and said it had

Two separate defects behind one misleading success message:

- `scripts/scrape_prior_league.py` never passed `no_cache`, so it could only
  re-parse soccerdata's cached HTML. The cache files are dated **2026-08-01**;
  a re-run on 2026-08-17 made no request. There is now a `--no-cache` flag.
- The ingest defaulted every missing FBref column to 0.0 and reported
  *"N player rows written"* regardless, so a scrape whose source carries no
  `Expected` columns looked identical to one that worked. It now names every
  per-90 metric that is zero on **every** row.

Row count is not evidence. soccerdata also caches **blocked** responses — the
cached Premier League *shooting* page in this project is a 4×3 fragment with
no stats table at all — so a "successful" scrape can be nothing whatsoever.

### 16. Non-penalty goals were in the scrape all along

`npxg90`/`xa90` genuinely are unavailable: no scraped league-season carries the
`Expected` group. But **`G-PK`** — realized non-penalty goals — was in the
standard table the whole time and was simply never read, while the cold start
fell back to goals *including* penalties.

`npg90` is now captured and preferred. Backfilled offline from the existing
cache across all 25 league-seasons: **7,329 of 15,323 rows populated, 1,043 of
them previously inflated by penalties.** Jack Clarke drops from 0.603 to 0.377
goals/90 (projection 4.45 → 3.64); George Hirst, on the GW1 bench, from 0.470
to 0.427.

### 17. FBref will never serve the expected-goals metrics — Understat does

A `--no-cache` re-fetch confirmed the flag now works (the cache file updated)
and settled the question: the freshly-fetched La Liga page is the **right**
page — `id="stats_standard"`, real squad tables — and its `data-stat`
attributes contain **no xG field at all**. No amount of re-scraping that
endpoint produces `npxg90`.

Understat has it, needs no browser, and is already this project's Premier
League xG source. It covers four of the five prior leagues (`ITA-Serie A`
needs a one-time `{"Understat": "Serie A"}` entry in
`~/soccerdata/config/league_dict.json`, the same registration the Championship
already needed for FBref).

On the set the cold start actually reads — coded, ≥450 minutes, 2025-2026:

| League | coverage |
|---|---|
| La Liga | 22/26 |
| Ligue 1 | 26/27 |
| Bundesliga | 19/19 |
| Serie A | 15/16 |
| **ENG-Championship** | **0/100** — Understat does not cover it; falls back to `npg90` |

Matching Understat names onto FPL codes is a new entity-resolution surface, so
a match is rejected when the two sources disagree by more than 25% on minutes
played — an independent check that it is the same footballer. It fired on 11
rows across the 20 league-seasons.

This also removed the reason the prior-league tier was excluded from the
cold-start penalty bonus: `npxg90` and `npg90` are non-penalty by
construction, so the duty is now additive rather than ambiguous. The guard is
the *input*, not the league — a row still falling through to raw `goals90`
keeps the exclusion.

## Fourth pass, 2026-08-17

### 18. The placeholder fix was applied at the wrong layer (self-inflicted)

Defect 14 was fixed by storing the neutral 1200 in place of FPL's zeros. That
put the FDR features on the right scale and silently broke something better:
`cold_start.load_current_defence_strength` treats an all-zero row as **absent**
— deliberately, and documented as such — so callers fall back to **prior-season**
strengths. Writing 1200 made `avg > 0` true for every team, so that fallback
never fired and real data for **17 of 20 teams** was replaced by a flat
constant. That, not any modelling improvement, is what changed the GW1 shape to
3-5-2: defenders had lost their fixture differentiation.

`0` is this project's established "not published" signal. The ingest stores the
bootstrap as-is again; `projection/features.py` honours the convention on
**read**, treating any strength below a plausibility floor as NULL so the
existing median/1200 fallback takes over. Fixture opponent strength is back to
14 distinct values spanning 1085–1355.

### 19. A re-run gameweek was scored once per re-run

Re-running appends a lineup row rather than replacing it — correct storage,
since every read takes the latest. But the outcome scorer selected **every**
unscored lineup row. Seven re-runs of GW1 left 8 rows in `decision_log` and
**689 in `sim_decision_log` for 90 real (persona, gameweek) pairs** — a 7.7×
inflation that `simulation/analysis.py` would have counted as independent
observations, skewing the persona ranking and the calibration sample with
decisions that were never live.

Only the latest lineup per (gameweek, persona) is scored now, and the
per-persona scoping is enforced rather than documented — the subquery resolves
`MAX(created_at)` within its scope, so an unscoped call would have collapsed
ninety personas to one.

produce it, and soccerdata's player-season API has no `goal_shot_creation`
stat type to get it from.

The 100 Championship rows have no expected-goals metrics and never will from

### Also closed

The three "known open decisions" in the GW1 checklist. Cold-start penalty duty
is implemented for takers **new** to the duty only — prior-season penalty xG
(`xg - npxg`) separates them from established takers whose points already
contain their penalties, and that separation only became trustworthy with the
shot-level npxG ingest in defect 7's fix. 25 qualify, 22 are excluded. It did
not change the GW1 squad.

The checklist's squad table was also stale: the **bench** it listed (Kelleher,
Furo, Scarlett) was not the bench in `decision_log`, so following the document
would have entered the wrong four players.

## What this says about the test suite

All seven defects passed 700+ tests. They were not code errors in the sense
tests catch — the code did what it was written to do. They were:

- **shared state changing behaviour elsewhere** (1 and 2),
- **a formula that was self-consistent but semantically inverted** (3),
- **inputs that were absent rather than wrong** (4),
- **an upsert key that silently merged two things** (5 and 6).

The weekly quality gate now covers the last three classes: source coverage by
minutes, dead columns, copied columns, referential integrity, and projection
sanity. The first class — a change to persisted state altering control flow —
is only caught by profiling the database, which is what this audit was.
