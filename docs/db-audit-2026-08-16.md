# Database audit — 2026-08-16

Full interrogation of `fpl_bot_v2.db` before the GW1 deadline: every table
profiled, every all-null and constant column explained, entity resolution
measured across sources, and time-sensitive data refreshed.

**Seven real defects found.** Four were mine, introduced earlier the same day.
The audit method that found them was profiling the data itself — every one had
passed the test suite.

---

## Defects found and fixed

### 1. A Triple Captain recorded as played in GW1

The worst of them. `decision_log` contained a `chip` row for gameweek 1,
before a ball had been kicked, so `chips_used_this_season()` believed the
chip was spent for the whole first half of the season.

Cause: making the cold start persist its projections (a display fix, so the
site and dashboard had numbers instead of nulls) meant `player_projections`
was no longer empty pre-season. `_run_decision_cycle` branched on
`projections.empty`, so it took the **in-season** path, ran `recommend_chip`,
and burned the chip.

Whether it is a cold start is a property of the *season*, not of what happens
to be persisted. Now branches on `season_has_played_history`.

### 2. Every persona writing the real bot's projections

Same root cause. `player_projections` has no persona scoping and
`get_latest_projections` takes `MAX(created_at)`, so whichever of the 90
personas ran last decided what the real bot, the site export and the
dashboard all read. **235,720 rows across 83 batches**; now 2,840 in one.

### 3. Clean-sheet probabilities were inverted

`_cs_from_h2h` computed `home_cs = draw + away_win * 0.3` — that is P(the
*home* team fails to score), attributing home clean sheets to away wins. A
fixture priced 0.806/0.132/0.062 returned **0.151 for the dominant side and
0.374 for the underdog**: inverted, and each side handed the other's number.
`features.py` feeds these to the minutes model as `my_cs_prob`/`opp_cs_prob`.

Replaced with the model's own Poisson — `exp(-λ_opponent)`, the same closed
form `assemble.py` uses — rather than a re-swapped heuristic. Same fixture now
gives 0.563 and 0.075.

### 4. The prior-league tier projecting everyone at the floor

`prior_league_stats` has `goals90`/`assists90` populated (7,413 and 7,097
non-zero rows) and `npxg90`/`xa90`/`sca90` **entirely zero** — the FBref
prior-league scrape only got the basic stats. `_prior_league_projection` used
precisely the zero ones, so all 28 league-tier players projected at the 2.0
floor and a genuinely good foreign signing was invisible to the optimiser.
Falls back to raw output; 57 players now clear the floor, topped by Rashford
at 4.31.

### 5. Two set-piece takers silently lost

The depth-chart file produced 102 roles and the table held 100.

- **Schär** is spelled "Schär" under free kicks and "Schar" under corners.
  Keyed by the raw name those became two roles for one player, and the upsert
  on `(player_id, season)` meant the second erased the first — his free-kick
  duty vanished.
- **"Pedro"** resolved to Pedro Neto on his first name, so João Pedro's
  penalty duty was assigned to Neto and then overwritten by Neto's own
  entries. **Chelsea's second penalty taker disappeared entirely.**

Variants now merge on the normalised name; genuine ambiguity is reported and
skipped rather than guessed.

### 6. `ß`/`æ`/`œ` dropped rather than transliterated

NFKD does not decompose them, so the ascii pass deleted them: **"Groß"
normalised to "gro"** — a truncated stem that cannot match an English source's
"Gross". Latent rather than live (our own spelling truncates identically), but
it would have bitten the first time a source spelled him the English way.

### 7. `cs_probability` never populated

Covered separately: `assemble.py` had each player's per-scenario clean sheet
internally but never surfaced it, so the column was 0.0 on every row ever
written and `plot_analysis.py`'s chart was permanently blank.

## Explained, not defects

| Observation | Why |
|---|---|
| `btts_prob` always NULL | The Odds API's `/odds` endpoint **rejects the market** (HTTP 422, verified). Cannot be sourced. `features.py` reads it via `COALESCE(..., 0.5)`, so it is a constant contributing nothing to the minutes model. |
| 20+ `player_match_events` columns all zero | FBref supplies defensive actions but not passing/chance stats. Affects only the historical bonus recompute, which still matches FPL's awarded bonus on **88.9%** of rows (mean error +0.012) — the missing inputs are largely compensated. |
| `teams.strength_*` all zero | FPL has not published them yet; `team_season_strength` is used instead. |
| `players.form`, `transfers_*` zero | Genuinely zero pre-season. |
| `fixtures.team_h_score` NULL, `finished` 0 | Season has not started. |
| `projection_samples` empty | The cold start produces no Monte Carlo draws. |
| `player_setpiece_roles.key_passes_per_game` zero | A published taker list has no opinion on key passes; the partial write leaves it for the Understat path. |
| `sim_managers.max_ownership_differential` constant | Not swept — it is inert until ownership data exists. |

## Follow-up, 2026-08-17

Re-auditing the odds path the next day turned up three more, including a
regression introduced by defect 3's own fix.

### 8. The clean-sheet fix was applied to serving but not training

Defect 3 corrected `data/ingestors/odds_api.py` (live) and left
`scripts/backfill_odds.py` (historical) alone — whose helper documented itself
as *"mirrors the live odds_api heuristic so historical and live features are on
the same scale"* and stopped doing so the moment the live one changed.

Both feed the same `my_cs_prob`/`opp_cs_prob` columns, so the minutes model was
fitting coefficients on inverted clean sheets and applying them to correct
ones. A consistent error a model can absorb; a **sign flip between fit and
inference** it cannot. Worse, briefly, than the original bug.

The derivation now lives once, in `projection/team_goals.py`, with both sites
calling it — a comment cannot hold an invariant that spans two files. Re-ran
the backfill: of 744 strong home favourites, **0** now have `home_cs <=
away_cs`.

### 9. Every odds feature was about to go inert for the whole season

`historical_fixture_odds` is a football-data.co.uk backfill of **finished**
seasons, so it ends at 2025-26. `minutes_model._build_features` calls
`load_fixture_odds()` and nothing else, on training and prediction alike — so
every 2026-27 row would have taken the `COALESCE` defaults: three constants,
for 38 gameweeks, in a model fitted on five seasons where they varied.

Nothing would have raised. A defaulted column is indistinguishable from a
populated one everywhere downstream. `fixture_odds` was full the whole time and
`load_live_odds_asof` existed for exactly this purpose, wired to nothing.

### 10. `btts_prob` was never a feature at all

Not merely unsourceable, as recorded above. The training table stored the
**over-2.5 probability under that name** — a documented proxy, and identical on
all 1900 rows — while the live API rejects the BTTS market, leaving it NULL and
pinned at 0.5 when served. So the model fitted a coefficient against a variable
spanning 0.341–0.81 and applied it to a constant. Replaced by `over25_prob`:
same signal, populated on both sides, under its own name.

### Also closed

The three "known open decisions" in the GW1 checklist. Cold-start penalty duty
is implemented for takers **new** to the duty only — prior-season penalty xG
(`xg - npxg`) separates them from established takers whose points already
contain their penalties, and that separation only became trustworthy with the
shot-level npxG ingest in defect 7's fix. 25 qualify, 22 are excluded. It did
not change the GW1 squad.

The checklist's squad table was also stale: the **bench** it listed (Kelleher,
Furo, Scarlett) was not the bench in `decision_log`, so following the document
would have entered the wrong four players.

## What this says about the test suite

All seven defects passed 700+ tests. They were not code errors in the sense
tests catch — the code did what it was written to do. They were:

- **shared state changing behaviour elsewhere** (1 and 2),
- **a formula that was self-consistent but semantically inverted** (3),
- **inputs that were absent rather than wrong** (4),
- **an upsert key that silently merged two things** (5 and 6).

The weekly quality gate now covers the last three classes: source coverage by
minutes, dead columns, copied columns, referential integrity, and projection
sanity. The first class — a change to persisted state altering control flow —
is only caught by profiling the database, which is what this audit was.
